# LeapSign v1.1 Implementation Plan

> Execution: inline using superpowers:executing-plans. The user explicitly
> authorizes local implementation without intermediate approval and conditional
> production release after all required gates. No v2 modifications.

**Goal:** Compare cryptographic PDF signature inventories before accepting a
normal turn, persist a recoverable receipt and expose dimensions independently.
**Architecture:** Existing Edge authorization/quota checks precede a separate
private v1-only validator; PostgreSQL commits receipt, version and inventory
atomically. A server flag defaults off and is authoritative inside acceptance.
**Tech Stack:** Existing React/Supabase/PostgreSQL; pyHanko 0.29.0 for independent
CMS/ByteRange/diff analysis, no new signing UI or private key upload.
**Spec:** User's full 13-section request in the attached Texto pegado.txt, read
in full; preserved source request is outside the application checkout.

## Global Constraints

- Worktree /workspace/worktrees/firmador-v1.1; branch feature/v1.1-signature-inventory.
- Start at origin/main 2f8048291bdc6230282d0ae2ba1f52bc96733bb3.
- Flag PDF_SIGNATURE_INVENTORY_ENABLED initially false. No production enablement
  without readiness, positive/negative live smoke, exact rollback and quotas.
- No paid services, no v2 infrastructure or secrets, no rewrite of signed PDFs.
- Exactly one new signature per normal turn; untrusted/expired/unknown-revocation
  is not synonymous with cryptographic corruption. No legal-validity claim.
- Existing v1 appearance, login, recovery, notifications and retention unchanged.

## Review Focus

1. First signature on a PDF without AcroForm: support safely without rewriting it.
2. Mathematically valid signature over changed content: reject content replacement.
3. Valid CMS but malformed ranges/unsigned tail: reject even if a library parses it.
4. Remote timeout after commit: receipt lookup must not require an active old turn.
5. Original PDF already signed: inherited inventory is not counted as new turns.
