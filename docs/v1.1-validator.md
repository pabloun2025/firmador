El 22 de octubre de 2026 se aplicó la migración y se desplegaron las funciones,
el validador y la interfaz sobre https://firma.veryfacil.org. La aceptación con
inventario está activa. Se comprobó online una cadena sintética de tres firmas,

## Contrato

Servicio exclusivo v1: `validator.inventory_service:app`.
POST `/validate` autenticado con `Authorization: Bearer <token exclusivo v1>`.
JSON exacto: previous (PDF base64), candidate (PDF base64), baseSha256.
Se rechazan campos adicionales; nunca P12, PFX, contraseñas o claves privadas.
Respuesta positiva: política leapsign-v1.1-integrity-offline-1, hashes padre/hijo,
inventario completo, firma nueva, heredadas y estados independientes. Una imagen
o texto impreso no cuentan como firmas. La aceptación normal exige una nueva.
Confianza `not_evaluated`, revocación `unknown`: no existe política de confianza
configurada en v1. No se afirma vigencia al momento declarado, timestamp fiable
ni validez jurídica. La vigencia reportada se evalúa al recibir el PDF.

La política compara firmas CMS normalizadas para IDs, rangos originales,
integridad matemática, revisión cubierta y cambios semánticos permitidos.
El original exacto se conserva como prefijo y su hash se verifica de nuevo.
No se modifica ningún PDF. PDF cifrado, contenido activo, cobertura incompleta,
malformación o diferencia no verificable fallan cerrado.

## Límites y operación

- PDF individual: 10 MiB; 500 páginas; 128 revisiones; 64 firmas regulares.
- Lectura HTTP JSON: 29 MiB, 15 s; validación: 20 s; salida: 256 KiB.
- Transporte Edge: una petición de hasta 90 s para tolerar un arranque en frío;
  sin reintentos ocultos ni pings para impedir la suspensión del plan gratuito.
- Reserva SQL: lease de 120 s, máximo tres intentos por turno. Un turno nuevo
  puede volver a intentarlo, sujeto siempre a las cuotas globales/de propietario.
- Una tarea simultánea por proceso, sin cola; hijo: CPU 15 s, AS 512 MiB.
- No usar réplicas para evadir cuotas globales; el transporte reserva en el
  ledger compartido antes de descargar el padre y de llamar al servicio.
- Cuotas iniciales: 200 validaciones/día globales, 50/propietario/día, 10/minuto
  globales; se consumen incluso con fallo. No son un tope de factura.
- Sin logs de acceso/cuerpos, persistencia de PDF, CORS ni documentación pública.
- TLS termina en Render. El endpoint requiere Bearer; no hay túnel de desarrollo.
  El plan gratuito no equivale a una red privada ni a disponibilidad garantizada.

Configuración dedicada, nunca VITE ni secretos v2:

```text
PDF_SIGNATURE_INVENTORY_ENABLED=true
V1_PDF_VALIDATOR_TOKEN=<guardar directamente en secretos, nunca aquí>
V1_PDF_VALIDATOR_URL=https://leapsign-v1-validator.onrender.com/validate
```

Se preparó primero readiness autenticada y el backend apagado, y se comprobó
el flujo anterior antes de activar el inventario. Edge exige
PDF_SIGNATURE_INVENTORY_ENABLED=true y la fila autoritativa
signature_inventory_settings.enabled=true. Si SQL está activo pero Edge no,
falla cerrado: nunca vuelve a aceptar solo por nombre/tamaño/páginas.
Un health 200 no equivale a una firma aceptada por el proceso.

Comando para el runtime aprobado (solo tras instalar las dependencias fijadas):

```sh
python -m uvicorn validator.inventory_service:app --host 127.0.0.1 --port 8092 --no-access-log
```

En Render, usar su terminación TLS y el comando siguiente; nunca quitar Bearer:

```sh
python -m uvicorn validator.inventory_service:app --host 0.0.0.0 --port $PORT --workers 1 --no-access-log
```

## Persistencia y recibos

Migración aplicada: 20261022010000_signature_inventory.sql; registrada también
en supabase_migrations.schema_migrations.

- signature_inventory_settings: interruptor SQL autoritativo, apagado por defecto.
- signature_validation_receipts: candidato/hash padre/sesión/lease/ruta privada,
  informe validado y recibo inmutable tras aceptación. Sin acceso del navegador.
- version_signature_inventories: resumen de conteos y relación incremental.
- version_pdf_signatures: registro público por firma/versión; solo su propietario.
- begin_signature_validation reserva antes de descargar/validar. Cada lease usa
  ruta distinta, subida sin upsert y limpieza de cuarentena a 48 h.
- commit_signature_validation registra versión, inventario, invitación y recibo
  en la transacción de aceptación existente. Si falla cualquier escritura, no
  avanza el turno. La versión aceptada nunca se elimina ante respuesta incierta.
- get_signature_receipt recupera por proceso/sesión/hash incluso tras caducar el
  turno o finalizar el proceso. No devuelve identidad de otras personas.
- Un trigger impide eludir el inventario por la RPC antigua mientras esté activo.

Las raíces/CRL/OCSP no se descargan ni renuevan automáticamente: no existe una
política de confianza v1 aprobada. Confianza no evaluada y revocación desconocida
siguen separadas de integridad. Quedan pendientes casos de revocación conocida
y política operativa; NO describirlos como comprobados ni importar raíces de v2.
